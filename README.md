# 🎪 운정 페스티벌 – 동아리 부스 체험전 웹앱

동아리 부스 안내, 예약, **QR 줄서기**, 혼잡도 확인을 하나로 묶은 모바일 웹앱입니다. 모드는 관람객, 부스 운영자, 관리자 세 가지입니다.

## 📘 운영 안내서 (guide.html)
보안 기능, 서버 장애 예방·대응, 웹 주소 바꾸기는 **`guide.html`**에 자세히 있어요. 주소 끝에 `guide.html`을 붙이면 열리고, 관리자 화면 위의 **📘 운영 안내서** 버튼으로도 열 수 있어요. Firebase와 상관없이 혼자 열리는 페이지라 서버가 멈춰도 볼 수 있어요.

## 부스 위치 (여러 곳 · 미정 · 관리자 자유 지정)
- 운영자는 **페이지 편집 → 3. 위치**에서 교실을 **여러 곳** 추가할 수 있어요. 다른 부스가 쓰는 교실은 고를 수 없어요.
- **위치 미정**을 체크하면 층별 안내도(지도)에는 나오지 않고, 부스 페이지·홍보·예약·줄서기는 그대로 공개돼요. 층별 안내 맨 아래 "위치가 아직 정해지지 않은 부스"에 모아서 보여 줘요.
- 관리자는 **부스 탭 → 위치 바꾸기**에서 어느 교실이든 지정할 수 있어요. 다른 부스와 같은 교실을 **함께 쓰게** 할 수도 있어요 (안내도에 +1 표시).

## 보안 (관리자 → 보안 탭)
로그인 연속 실패 잠금, 과다 요청 제한, 보안 로그, 기기 차단(서버 규칙으로 강제), 자동 차단이 들어 있어요. **firestore.rules가 바뀌었으니 Firebase 콘솔에 다시 붙여넣고 게시하세요.**

## 서버 장애 대비
- 오프라인 저장, 화면이 꺼지면 연결 쉬기, 관람객 접속 집계 끄기(기본), 사진 압축으로 서버 사용량을 줄였어요.
- 화면 위 띠로 인터넷 끊김·사용량 초과·비상 운영을 알려요.
- **비상 모드:** GitHub에서 `js/emergency.js`의 `on: false`를 `on: true`로 바꾸면, Firebase가 멈춰도 모든 화면에 안내가 뜨고 앱 접수가 멈춰요.
- 관리자 → 설정 / 예약 탭의 **비상용 명단 인쇄**로 예약자·대기자 명단을 종이로 뽑아 두세요.
- 관람객이 수백 명이면 무료 요금제 한도를 넘을 가능성이 높아요. **Blaze 요금제 + 예산 알림**을 권해요 (guide.html의 사용량 계산기 참고).

## 예약 (날짜 · 시간대 · 인원수 · 전화번호)
- 관람객은 **① 날짜 → ② 시간대 → ③ 인원수 · 전화번호 · 이름** 순서로 예약합니다.
- 회차 정원은 **사람 수** 기준입니다. 3명이 예약하면 남은 자리가 3 줄어듭니다.
- 관리자 → **예약** 탭에서 바꿀 수 있는 것:
  - **예약 날짜**: 여러 날을 추가하거나 빼고 저장하면 모든 예약 부스의 회차가 새 날짜로 만들어집니다.
  - **예약 규칙**: 예약 마감(회차 시작 몇 분 전), 1건당 최대 인원, 1인당 예약 수, 노쇼 유예.
  - **부스별 현황**: 예약 접수 열기·마감, 이 부스만 초기화, 회차별 정원 변경·예약 막기, 예약자 입장·노쇼·취소.
  - **운영 초기화**: 예약 · 줄서기 · 운영 상태를 골라서 **오늘 기준으로 새로 시작**합니다. "초기화"라고 입력해야 실행되며, 직전 상태는 자동 백업에 남습니다.
- 처음 실행하거나 이전 버전 데이터가 있는 브라우저에서 열면 **오늘 날짜 기준으로 예약이 비어 있는 상태**에서 시작합니다. 부스 페이지·계정·공지는 유지됩니다.
- 회차는 기본 10:00~16:00입니다. 오늘 운영 시간이 이미 지났다면 관리자 → 예약 탭에서 내일 날짜를 추가하세요.

## QR 코드 만들기 · 삭제 (관리자 → QR 코드 탭)
- QR에는 부스마다 무작위 값이 들어간 주소(`#/qr/부스ID/값`)가 담깁니다.
- **다시 만들기**나 **삭제**를 하면 이미 인쇄한 예전 QR은 "사용할 수 없는 QR 코드"로 안내됩니다. 잘못 붙였거나 잃어버린 QR을 막을 때 쓰세요.
- "QR 없는 부스 모두 만들기", "만든 QR 모두 인쇄", "모든 QR 삭제"도 있습니다.

## 화면 상단 시계
- 가상 시각이 아니라 **이 기기의 현재 날짜와 시각**을 보여 줍니다 (예: `10.19 (월) 12:09`).
- 관리자가 시연용 가상 시각을 켜 두면 옆에 `시연 10:40`처럼 작게 함께 표시됩니다.

## 휴대폰 화면
- 휴대폰에서도 PC와 같은 구성입니다. 상단 메뉴, 가운데 큰 제목, 아래 정보 한 줄, 둘러보기 메뉴 3칸이 그대로 나옵니다.
- 큰 제목은 화면 폭에 비례해 PC와 같은 비율로 줄어들고, 본문 글자는 13px 아래로 줄이지 않아 흐려지거나 깨지지 않습니다.

## QR 줄서기와 자동 혼잡도
혼잡도는 사람이 입력하지 않고 **자동으로 계산**됩니다.

| 부스 종류 | 혼잡도 기준 | 기본값 (관리자 → 설정에서 변경) |
|---|---|---|
| 당일 부스 | QR 줄서기 대기 인원 | 5명 이상 보통, 15명 이상 혼잡 |
| 예약 부스 | 다가오는 3회차 예약률 | 50% 이상 보통, 90% 이상 혼잡 |

**흐름**
1. 관리자 → **QR 코드** 탭에서 부스별 QR 코드를 인쇄해(A4 한 장에 4개) 부스 입구에 붙입니다.
2. 관람객이 QR을 찍으면 줄서기 화면(`#/q/부스ID`)이 열리고, 이름을 넣으면 **대기 번호표**를 받습니다. 줄에 서 있지 않고 다른 부스를 둘러봐도 됩니다.
3. 운영자 → **QR 줄서기** 탭에서 자리가 날 때 **다음 손님 호출**을 누릅니다. 단체 체험은 여러 명을 한꺼번에 호출할 수 있습니다.
4. 호출된 관람객 휴대폰에는 초록색 알림 띠, 진동, 소리가 나옵니다. 알림을 허락했다면 시스템 알림도 뜹니다.
5. 손님이 오면 **입장**을 누릅니다. 호출 후 5분 안에 오지 않으면 자동으로 노쇼 처리됩니다.

- 휴대폰이 없는 손님은 운영자가 **현장 등록**으로 번호표를 대신 발급합니다.
- **줄서기 접수 마감**을 누르면 새 번호표 발급만 멈추고, 이미 받은 번호표는 그대로 유지됩니다.
- 대기자가 있는데 15분 동안 호출이 없으면 관리자 대시보드에 경고가 뜹니다.
- QR은 **인터넷에 공개한 주소(GitHub Pages)에서** 인쇄하세요. `localhost`나 `127.0.0.1` 주소의 QR은 다른 휴대폰에서 열리지 않습니다.
- QR을 찍은 휴대폰들이 같은 줄을 보려면 **서버 모드**가 필요합니다. 로컬 모드는 한 브라우저 안에서만 시연할 수 있습니다.
- 서버 모드에서 관람객의 "앞에 몇 명"은 공개된 숫자로 계산한 추정치입니다. 앞사람이 취소하면 실제로는 더 빨리 차례가 옵니다.

## 두 가지 실행 모드
| | 로컬 모드 (기본) | 서버 모드 (Firebase) |
|---|---|---|
| 설정 | 아무것도 안 해도 됨 | `js/firebase-config.js` 채우기 |

| 용도 | 연습, 시연, 디자인 수정 | **실제 행사** |

## 1. 내 컴퓨터에서 실행하기 (VS Code)
1. VS Code → `파일 > 폴더 열기` → `unjeong-festival` 폴더 선택
2. 확장(Extensions)에서 **Live Server** 설치
3. `index.html` 우클릭 → **Open with Live Server**

### 미리 준비된 계정
| 역할 | 아이디 | 비밀번호 | 바꾸는 곳 |
|---|---|---|---|
| 관리자 | `meyun` | `1234` | `js/data.js`의 `ADMIN_ID`, `ADMIN_PW` |
| 부스 운영자 | `booth01` ~ `booth10` | `1234` | 관리자 → 계정 탭 (`OP_DEFAULT_PW`가 기본값) |
| 참여자 | 학번+이름 (예: `20315홍길동`) | 본인이 정함 | 로그인 → **참여자 회원가입** |

- 화면 오른쪽 위 **LOGIN** 버튼 하나로 세 역할 모두 로그인합니다.
- 관리자는 **계정 탭**에서 운영자 아이디와 비밀번호를 직접 정해 만들 수 있습니다.
- 참여자 아이디는 **학번 5자리 + 한글 이름**입니다. 같은 학번은 한 번만 가입할 수 있습니다.
- 가입 화면에는 **본인 확인과 명의 도용 경고**가 있으며, 체크해야 가입됩니다.
- 기본 설정에서는 **예약할 때 참여자 로그인이 필요**합니다. 관리자 → 설정에서 끌 수 있습니다.

### 학교 건물(층별 안내) 고치기
`js/data.js`의 `BUILDINGS`에 **본관과 후관 1~5층**이 교실 배치도대로 적혀 있습니다.
- `'2-1'` → 부스를 열 수 있는 교실
- `'홈베이스|2'` → 너비 2배
- `'~화장실'` → 편의시설 (회색, 부스 불가)
- `'|1.5'` → 빈 공간

## 백업 · 복구 (데이터가 망가졌을 때)
관리자 → **설정** → **백업 · 복구**

| 버튼 | 만들어지는 파일 | 내용 |
|---|---|---|
| 엑셀로 내려받기 | `UJHS_backup_날짜_시각.xlsx` | 시트별 표: 안내 · 설정 · 부스 · 회차 · 예약 · 줄서기 · 번호표 · 공지 · 계정 (사진 제외) |
| JSON으로 내려받기 | `UJHS_backup_날짜_시각.json` | 사진까지 포함한 완전한 백업 |
| 파일 고르기 | (올리기) | .xlsx 또는 .json을 고르면 그 시점으로 복구 |

- 파일은 브라우저의 **다운로드 폴더**에 저장됩니다. USB, 구글 드라이브, 학교 PC 등 **다른 곳에도 복사**해 두세요.
- **엑셀 파일은 직접 고쳐서 올려도 됩니다.** 부스 이름이나 교실을 바꾸면 그대로 반영됩니다. 맨 위 머리글 줄은 바꾸지 마세요.
- 엑셀 파일에는 사진이 없습니다. 엑셀로 복구하면 같은 부스ID의 **지금 사진이 그대로 유지**됩니다.
- 관리자 화면을 열어 두면 **30분마다 자동 백업**됩니다. 이 브라우저에 최근 3개가 보관되며, 복구나 초기화 직전에도 자동으로 하나 남깁니다.
- `backup/UJHS_initial_data.xlsx`와 `.json`은 **처음 상태**(예시 부스 10개, 예약 없음)입니다.

## 2. 서버 연결하기 (Firebase, 약 15분)

### ① 프로젝트 만들기
1. https://console.firebase.google.com 접속 → 구글 계정 로그인
2. **프로젝트 추가** → 이름 `unjeong-festival` → (Google 애널리틱스는 꺼도 됨) → 만들기

### ② 로그인 방식 켜기
1. 왼쪽 메뉴 **빌드 > Authentication** → 시작하기
2. **로그인 방법** 탭에서 아래 두 가지를 **사용 설정**
   - **이메일/비밀번호** (운영자·관리자 로그인용)
   - **익명** (관람객이 회원가입 없이 예약하는 데 사용)

### ③ 데이터베이스 만들기
1. **빌드 > Firestore Database** → 데이터베이스 만들기
2. 위치: **asia-northeast3 (서울)** 선택
3. **프로덕션 모드**로 시작
4. 만들어지면 **규칙(Rules)** 탭 → 내용을 모두 지우고 이 폴더의 **`firestore.rules` 파일 내용을 전부 붙여넣기** → **게시**
   (QR 줄서기와 인원수 예약 기능이 추가되면서 규칙이 바뀌었습니다. 예전 규칙을 쓰고 있다면 **다시 붙여넣고 게시**하세요.)

### ④ 웹앱 등록하고 설정값 복사
1. 프로젝트 개요 옆 ⚙️ **프로젝트 설정** → 아래쪽 **내 앱** → 웹 아이콘 `</>` 클릭
2. 앱 닉네임 입력 → 앱 등록 (Hosting 체크는 안 해도 됨)
3. 화면에 나온 `firebaseConfig = { apiKey: ..., ... }` 값을
   **`js/firebase-config.js`** 에 그대로 옮겨 적고 저장

```js
window.FIREBASE_CONFIG = {
  apiKey: 'AIza....',
  authDomain: 'unjeong-festival.firebaseapp.com',
  projectId: 'unjeong-festival',
  storageBucket: 'unjeong-festival.appspot.com',
  messagingSenderId: '1234567890',
  appId: '1:1234567890:web:abcdef',
};
```
> 이 값은 공개돼도 괜찮습니다. 누가 무엇을 할 수 있는지는 ③에서 넣은 보안 규칙이 막아줍니다.

### ⑤ 처음 설정
1. Live Server로 다시 열면 **"처음 설정"** 화면이 나옵니다.
2. 관리자 아이디와 비밀번호(6자 이상)를 정합니다.
   "예시 부스 10개 넣기"는 체크한 채로 시작하면 구조를 파악하기 쉽습니다.
3. 관리자 화면 → **🔑 계정** → **"계정 없는 부스에 일괄 발급"** → 나온 아이디·비밀번호를 각 동아리에 전달합니다.
4. 실제 동아리를 추가하려면 같은 화면의 **새 부스 계정 만들기**를 씁니다. 예시 부스는 관리자 → 부스에서 비공개로 돌리면 됩니다.

## 3. 인터넷에 공개하기 (GitHub Pages, 무료)
1. https://github.com 가입 → 오른쪽 위 **+ > New repository**
   이름 `unjeong-festival`, **Public** → Create
2. **uploading an existing file** 클릭 → `unjeong-festival` 폴더 **안의 파일과 폴더 전부**를 끌어다 놓기
   (`index.html`이 저장소 맨 위에 있어야 함) → Commit changes
3. 저장소 **Settings > Pages** → Branch를 `main` / `(root)` 로 선택 → Save
4. 1~2분 뒤 `https://내아이디.github.io/unjeong-festival/` 주소가 생깁니다.
5. 이 주소로 **QR 코드**를 만들어 포스터, 부스 앞, 계단에 붙이세요.

수정할 때는 파일을 다시 업로드하면 1~2분 뒤 자동으로 반영됩니다.

## 4. 행사 당일 전 체크리스트
- [ ] 휴대폰 2~3대로 관람객 예약 → 운영자 입장 처리 → 관리자 화면 확인 리허설
- [ ] 휴대폰 2~3대로 QR 줄서기 → 운영자 호출 → 관람객 알림 → 입장 처리 리허설
- [ ] 관리자 → QR 코드에서 공개 주소 기준 QR을 인쇄해 부스 입구에 부착
- [ ] 관리자 → 예약 → **운영 초기화**로 리허설 기록을 지우고 행사 날짜 기준으로 새로 시작
- [ ] 관리자 → 설정에서 **가상 시각을 "실제 시각으로"** 되돌렸는지 확인
- [ ] 예시 부스는 비공개 처리, 실제 부스는 모두 **승인·공개**
- [ ] 운영자 계정 배포, 각 부스에 휴대폰 1대 이상
- [ ] 서버 장애 대비 종이 예약표 백업
- [ ] (권장) 아래 요금 안내를 보고 Blaze 요금제와 예산 알림 설정

## 5. 비용 안내
Firebase 무료(Spark) 요금제는 **하루 읽기 5만 회, 쓰기 2만 회**까지입니다.
- 연습이나 소규모 리허설은 무료로 충분합니다.
- 관람객이 **수백 명** 동시에 쓰면 무료 한도를 넘을 수 있습니다. 한도를 넘으면 그날은 앱이 멈춥니다.
- 행사 전에 **Blaze(종량제)** 로 바꾸고 **예산 알림을 1~5달러**로 걸어 두기를 권장합니다.
  500명 규모의 하루 행사라면 대략 1달러 이하로 예상되지만 실제 사용량에 따라 달라집니다.
  (Firebase 콘솔 → 사용량 및 결제에서 확인)
- 결제 수단 등록이 필요하므로 **선생님과 상의**하세요.

## 보안 규칙이 막아주는 것
- 관람객은 **본인 예약만** 볼 수 있습니다. 다른 사람의 이름이나 번호는 보이지 않습니다.
- 운영자는 **자기 부스만** 수정하고 자기 부스 예약자만 볼 수 있으며, 공개 승인은 할 수 없습니다.
- 공지 작성, 부스 승인, 계정 발급은 **관리자만** 할 수 있습니다.
- 마지막 한 자리를 여러 명이 동시에 예약해도 **정원을 넘지 않습니다**(서버 트랜잭션).
- 여러 명이 동시에 줄을 서도 **대기 번호가 겹치지 않습니다**(서버 트랜잭션).
- 관람객은 **자기 번호표만** 볼 수 있고 취소만 할 수 있습니다. 호출·입장·노쇼 처리는 그 부스 운영자와 관리자만 할 수 있습니다.

## 알아둘 점
- 서버 모드에서 "재발급"을 누르면 **새 아이디**(예: `booth01-2`)로 다시 발급됩니다. 브라우저에서는 다른 사람의 비밀번호를 바꿀 수 없기 때문입니다. 로컬 모드에서는 계정 탭에서 비밀번호를 바로 고칠 수 있습니다.
- Firebase는 비밀번호가 6자 이상이어야 해서, 앱이 내부적으로 뒤에 문자를 덧붙여 저장합니다. 사용자는 `1234`처럼 짧게 입력해도 됩니다.
- 로컬 모드는 비밀번호가 브라우저에 그대로 저장되는 **연습용**입니다. 실제 행사는 서버 모드로 하세요.
- 관람객의 "내 예약"은 그 휴대폰 브라우저에 연결됩니다. 다른 폰이나 시크릿 창에서는 보이지 않습니다.
- 사진은 서버 용량 제한 때문에 자동으로 작게 줄여서 저장됩니다.
