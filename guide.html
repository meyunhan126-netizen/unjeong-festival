🔐 보안 기능 안내

이 앱은 이상한 접속 시도를 세 겹으로 막아요. 앱이 먼저 막고, 앱을 고쳐서 우회하려 해도 서버 규칙이 막고, 그 위에서 Firebase가 비밀번호와 데이터를 지켜요.

① 앱이 막기로그인을 연속으로 틀리면 잠그고, 너무 잦은 예약·줄서기를 잠시 멈춰요. 이상한 시도는 보안 로그에 남아요.
② 서버 규칙이 막기차단된 기기, 권한이 없는 수정은 Firebase 보안 규칙(firestore.rules)이 거절해요. 앱을 고쳐도 소용없어요.
③ Firebase가 지키기비밀번호는 Firebase가 보관하고, 같은 계정에 시도가 몰리면 Firebase가 스스로 잠시 막아요.

위험 점수 계산해 보기

한 기기가 최근 1시간 동안 한 일을 넣어 보세요. 점수가 기준 이상이면 자동 차단돼요.

이럴 땐 이렇게

누군가 계속 로그인을 시도해요
  1. 관리자 → 보안 탭의 "주의할 기기"에서 시도한 아이디와 기기를 확인해요.
  2. 점수가 높으면 차단을 눌러요 (자동 차단이 이미 했을 수도 있어요).
  3. 공격받은 계정의 비밀번호를 바꿔요. 운영자 계정은 관리자 → 계정 → 재발급(예전 아이디는 못 쓰게 됨)이 가장 확실해요.
운영자 비밀번호가 다른 사람에게 알려졌어요
  1. 관리자 → 계정 → 그 부스 계정 재발급 → 새 아이디·비밀번호를 그 동아리에만 전달해요.
  2. 관리자 → 부스에서 그 부스 페이지가 이상하게 바뀌지 않았는지 확인해요. 이상하면 설정 → 백업에서 복구해요.
관리자 비밀번호가 알려졌어요 (가장 위험)
  1. 즉시 앱의 비밀번호 변경으로 관리자 비밀번호를 바꿔요.
  2. 로그인이 안 되면(누군가 이미 바꿨다면) Firebase 콘솔 → 보안 → Authentication → 사용자 목록에서 관리자아이디@unjeong.app 줄의 ⋮ → 계정 사용 중지를 눌러 막아요.
  3. 관리자 → 설정 → 백업 · 복구로 데이터가 망가지지 않았는지 확인해요.
예약이나 줄서기가 이상하게 몰려요 (장난 예약)
  1. 관리자 → 보안 탭에서 같은 기기가 반복하는지 보고 차단해요.
  2. 관리자 → 예약 탭에서 이상한 예약을 취소해요. 자리가 다시 열려요.
  3. 계속되면 관리자 → 설정에서 "예약·줄서기할 때 참여자 로그인 필요"를 켜요. 학번+이름 계정이 있어야만 예약할 수 있어요.

솔직하게 알아 둘 한계

• 기기 기준이에요. 다른 휴대폰으로 오면 새로 감지해요. 그래서 "로그인 필요" 설정과 함께 쓰면 더 확실해요.
• 자동 차단은 관리자 화면이 열려 있을 때만 동작해요. 무료 요금제에서는 서버 쪽 프로그램을 돌릴 수 없어서, 관리자 기기가 대신 판단해요. 그래도 차단 자체는 서버 규칙이 강제해요.
• 더 강하게 막고 싶다면 Firebase App Check(reCAPTCHA)를 켤 수 있어요. 진짜 우리 앱에서 온 요청만 받게 해 줘요. 설정이 조금 복잡하니 필요하면 따로 요청하세요.

비상 모드 켜는 법 (Firebase가 멈춰도 동작)

  1. GitHub 저장소 → js 폴더 → emergency.js → 오른쪽 위 연필(✏️) 버튼을 눌러요.
  2. on: false 를 on: true 로 바꾸고, message 에 안내 문구를 적어요. 
    window.EMERGENCY = {
  on: true,
  message: '서버 점검 중이에요. 예약·줄서기는 부스 앞에서 종이로 접수해요.',
};
  3. Commit changes → 1~2분 뒤 모든 휴대폰 화면 위에 빨간 안내 띠가 뜨고, 앱 예약·줄서기 접수가 멈춰요. (운영자·관리자 화면은 그대로 쓸 수 있어요)
  4. 복구되면 다시 on: false 로 바꾸고 Commit changes.

Blaze(종량제)로 바꾸는 법

  1. Firebase 콘솔 왼쪽 아래 Spark · 업그레이드 → Blaze 요금제 선택 → 결제 계정(카드) 연결. 선생님과 상의하세요.
  2. 바로 이어서 예산 알림을 만들어요: Google Cloud 콘솔 → 결제 → 예산 및 알림 → 예산 5,000원(또는 $5) · 50% · 90% · 100% 알림 → 저장.
  3. Blaze도 매달 무료 사용량은 그대로 있어서, 작은 행사는 대부분 0원~몇백 원이에요. 예산 알림은 "넘으면 알려 주는" 장치이고 자동으로 멈추지는 않아요.
정확한 요금은 Firebase 요금 안내에서 확인하세요. 위 계산기의 금액은 대략적인 값이에요.

복구된 뒤 확인할 것

  • 비상 모드를 켰다면 끄기 (emergency.js → on: false)
  • 종이로 받은 예약·번호표를 관리자 화면에 옮기거나, 현장에서 종이 순서대로 마무리하기
  • 관리자 → 보안 탭에 이상한 기록이 없는지 보기
  • JSON 백업 한 번 더 받기

🌐 웹 주소 바꾸기

GitHub Pages 주소는 https://계정이름.github.io/저장소이름/ 모양이에요. 그래서 meyunhan126-netizen 부분을 unjeongfestival-netizen 으로 바꾸려면, 그 이름의 GitHub 계정(조직)으로 저장소를 옮기면 돼요.

주소
지금https://meyunhan126-netizen.github.io/unjeong-festival/#/op/edit
바꾼 뒤https://unjeongfestival-netizen.github.io/unjeong-festival/#/op/edit
개인 아이디는 그대로 두는 방법(조직 만들기)을 권해요. 개인 계정 이름을 바꾸는 방법도 있지만, 내 다른 저장소 주소까지 모두 바뀌어요.

바꾸는 순서 (약 10분)

  1. 조직 만들기: GitHub 오른쪽 위 + → New organization → Free 요금제 → Organization name 에 unjeongfestival-netizen 입력 → 이메일 입력 → "My personal account" 선택 → Next. (이름이 이미 쓰이고 있다고 나오면 다른 이름을 정해야 해요)
  2. 저장소 옮기기: 지금 저장소(unjeong-festival) → Settings → 맨 아래 Danger Zone → Transfer ownership → Select one of my organizations에서 unjeongfestival-netizen → 저장소 이름 확인 입력 → Transfer.
  3. Pages 다시 확인: 옮긴 저장소 → Settings → Pages → Branch가 main / (root) 인지 확인하고, 아니면 다시 Save. 1~2분 뒤 새 주소가 나와요.
  4. Firebase에 새 주소 등록: Firebase 콘솔 → 보안 → Authentication → 설정 → 승인된 도메인 → 도메인 추가 → unjeongfestival-netizen.github.io. 확인이 끝나면 예전 meyunhan126-netizen.github.io 는 지워도 돼요.
  5. QR 다시 인쇄: 새 주소로 접속 → 관리자 → QR 코드 → "만든 QR 모두 인쇄". QR은 지금 열린 주소로 그려지므로, 예전 주소에서 인쇄한 QR은 바꿔 붙여야 해요.
  6. (선택) 예전 주소 자동 이동: 예전 주소로 들어온 사람을 새 주소로 보내려면, 개인 계정에 unjeong-festival 이라는 이름으로 새 저장소를 만들고, 함께 드린 old-address-redirect/index.html 파일 하나만 올린 뒤 Pages를 켜요. #/op/edit 같은 뒷부분도 그대로 넘겨줘요.
  7. 동료들에게 새 주소를 알리고, 사용설명서의 주소도 바꿔요.
저장소를 옮기면 GitHub가 저장소 주소(github.com/…)는 자동으로 넘겨주지만, Pages 사이트 주소(…github.io)는 넘겨주지 않을 수 있어요. 그래서 6번의 자동 이동 페이지를 만들어 두는 게 안전해요.

코드에는 주소가 적혀 있지 않아서(앱이 지금 열린 주소를 스스로 알아냄) 앱 파일은 고칠 필요가 없어요. Firebase 데이터도 그대로예요.
